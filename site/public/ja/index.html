Topophany — ターミナルで読むセルフホスト型ネットワーク監視

どこから、どの経路で、何に届いたのか — そして、何を根拠に。

ネットワークとサービスをセルフホストで監視し、ターミナルで読む。Go のバイナリ 1 つで依存なし。チェックが通るまで緑にはなりません。

インストール GitHub
$ go install github.com/WhitenWhiten/topophany/cmd/topo@latest

ドラッグで地球を回せます

01 ターミナル UI

どこかおかしい？ それはどこ？

topo preview の録画です。本物の TUI に、合成の根拠を流しています。

障害が起きる

x を押すと、自宅からロサンゼルスの中継回線への接続が遮断されます。確定した失敗だけが赤くなります。

1–9 チャプター space 一時停止。topo preview で自分でも試せます。

03 構成

1 つのバイナリ、3 つの役割

topo はクライアントであり、コレクターであり、観測点です。CGO も、データベースも、外部モジュールも不要。

  • バイナリクライアント、コレクター、ワーカー
  • 外部 Go モジュール標準ライブラリのみ
  • リリースビルドLinux、macOS、Windows · amd64、arm64
  • タブマウス対応

観測点

コレクター

クライアント

topo worker自宅のノート PC
topo worker東京のサーバー
topo serve --observerコレクター自身の基準
観測結果。分断の間はバッファ
topo serveジャーナル A · ACK の前に fsync
topo serveジャーナル B · 独立
読み取り専用のスナップショット
topoTUI、フェイルオーバー付き
topo --jsonスクリプト向けのスナップショット

2 つのコレクター、合意形成の芝居はなし

ワーカーは両方に送り、片方が落ちている間はバッファします。

設計からして読み取り専用

リモートの設定 API もシェルもありません。トポロジーはレビューするローカル JSON です。

上限があり、それを明言する

上限に達すると、根拠を捨てずにエラーで計測を止めます。

05 インストール

1 分で動く

ビルド済みアーカイブ、または go install ひとつで。

$go install github.com/WhitenWhiten/topophany/cmd/topo@latest

Go 1.26.9 以降が必要です。

Linux、macOS、Windows の amd64 と arm64。SHA256SUMS.txt 付き。

最新リリース
$ git clone https://github.com/WhitenWhiten/topophany $ cd topophany $ go build -trimpath -o topo ./cmd/topo

ドキュメント

  • ユーザーガイドTUI、編集、デプロイ (英語)
  • リファレンス設定と API (英語)
  • 運用コレクターとワーカーのデプロイ (英語)
  • セキュリティモデル境界、トークン、通信 (英語)

  1. 見て回る

    組み込みのデモ。x で何かを壊してみてください。

    $topo preview

  2. コレクターを起動する

    127.0.0.1:7447 でデモを動かします。

    $ topo init --dir ./demo $ topo serve --config ./demo/topology.json \ --auth ./demo/auth.json \ --data ./demo/collector-data \ --observer demo

  3. TUI を開く

    別のターミナルで。

    $topo --credentials ./demo/credentials.json
