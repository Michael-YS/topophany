Topophany — 場所の顕現

どこから、どの経路で、何に届いたのか — そして、何を根拠に。

ネットワークトポロジーとサービスの可用性をセルフホストで監視し、ターミナルで読み取ります。依存関係のない Go のバイナリ 1 つが、クライアントにも、コレクターにも、観測点にもなります。何が、どこから、どれだけ最近に測られたのかを伝え、通っていないチェックを緑で示すことはありません。

インストール GitHub でソースを見る
$ go install github.com/WhitenWhiten/topophany/cmd/topo@latest

ドラッグで地球を回せます

01 ターミナル UI

どこかおかしい？ それはどこ？

Overview は、一語も読まないうちに答えます：判定、すべての場所と経路の地図、そして対処が必要なものの短いリスト。下にあるのは、TUI 自身のレンダラーで 1 フレームずつ記録した topo preview です。根拠は合成ですが、本物の状態エンジンを通っています。

障害が起きる

すべて正常な状態から、x でプレビューを DMIT 回線が中国本土から遮断されるシナリオに切り替えます。チェックはサンプルごとに 1 つずつ失敗し、確定した失敗だけが赤くなります。タイムラプスで表示しています。

1–9 チャプター m 地図 v 視点 x シナリオ space 一時停止。ターミナル内のタブもクリックできます。本物は topo preview で試せます。

02 セマンティクス

色ではなく根拠を

健全性、根拠の出どころ、その鮮度はそれぞれ別のフィールドです。通過したチェックなしに緑になるものはなく、誰も監視していないサービスは unknown のまま、キャッシュされた表示はそうと明示されます。

初めから緑のものはない

正常な行では状態の列が空のままなので、光る言葉は問題だけです。登録されていてもチェックのないサービスは、稼働中ではありません。登録済み・未監視です。

観測点を明示する

各観測点は、実際にいる場所から測ります。自宅から見えた失敗はその経路の障害であってサーバーの停止ではなく、インシデントにはまだ到達できている観測点が示されます。

エッジが応答した

訪問者 Cloudflare NRT S1 オリジン
● HTTP 521 · エッジは稼働 ▲ 影響あり

Cloudflare や Vercel などの CDN の背後では、エッジからの応答はエラーページであってもエッジの稼働を証明するだけです。オリジンの根拠になるのは、エッジがキャッシュから返したのではない成功応答だけ。プローブは、どのエッジがどこから応答したかを記録します。

推測は推測と明記する

FAILED CHECKS
m-exit-dmit-aaitr

OTHER-OBSERVER RESPONSE EVIDENCE
w-exit-s2-aaitr, w-exit-s2-qqpr

HYPOTHESIS (NOT A FINDING)
source/path-specific interference, filtering or
routing fault is possible; blocking authority and
untested protocols are not established
No inference about all IP ports, untested UDP,
physical power or GFW authority.

インシデントには、失敗したチェックと、ほかの観測点からまだ見えているものが含まれます。誰もテストしていないポートやプロトコルについて推論することはありません。

主張しないこと

TCP 接続が受け付けられた
接続が確立したということだけ。アプリケーションプロトコルでも、プロキシ認証でも、経路全体でもありません。
リクエストは成功したが、出口 IP がポリシー外
policy という結果になります。到達性と出口ポリシーは別々に判定されます。
観測点が報告を止めた
その視点は stale になり、続いて unknown になります。遠隔の資産が down とされることはありません。
主経路が失敗し、候補が成功した
候補は利用可能で、冗長性は縮退しています。本番のトラフィックが切り替わったとは主張しません。
コレクターに到達できない
キャッシュされた表示は残って CACHED と示され、すべての項目が unknown になります。

03 構成

1 つのバイナリ、3 つの役割

CGO も、データベースのデーモンも、Node.js も不要で、外部の Go モジュールはゼロ。topo はターミナルクライアントであり、コレクターであり、観測点でもあります。クライアントを閉じても監視は止まりません。

  • バイナリクライアント、コレクター、ワーカー
  • 外部 Go モジュール標準ライブラリのみ
  • リリースビルドLinux、macOS、Windows · amd64、arm64
  • タブ30×10 から使え、マウスにも対応

観測点

コレクター

2 つのコレクター、合意形成の芝居はなし

ワーカーは両方のコレクターにそれぞれ届け、上限のある送信箱にバッファします。重複は観測 ID で除かれ、構成リビジョンが合わない記録は隔離されます。

設計からして読み取り専用

リモートの設定 API も、リモートシェルも、自動修復もありません。トポロジーはレビュー済みのローカル JSON にあり、topo edit で編集し、topo validate で確認します。

上限があり、それを明言する

既定では 24 時間分または 20,000 件の生データを保持し、ワーカーの送信箱には 32 MiB を割り当てます。上限に達すると、根拠を捨てる代わりにエラーで計測を止めます。

05 インストール

1 分で動く

Linux、macOS、Windows 向けのビルド済みアーカイブ、または go install ひとつで。デモは自分自身のループバック API だけを計測し、実行のたびに新しい認証情報を生成します。

$go install github.com/WhitenWhiten/topophany/cmd/topo@latest

Go 1.26.9 以降が必要です。ビルドでモジュールはダウンロードされません。

amd64 と arm64 の Linux、macOS、Windows 向けアーカイブ。それぞれに SHA256SUMS.txt が付きます。

最新リリース
$ git clone https://github.com/WhitenWhiten/topophany $ cd topophany $ go build -trimpath -o topo ./cmd/topo

  1. 見て回る

    組み込みのトポロジーと合成の根拠で、TUI のすべてを。x を押して何かを壊してみてください。

    $topo preview

  2. コレクターを起動する

    デモ用のトポロジーと新しい認証情報を書き出し、127.0.0.1:7447 で待ち受けます。

    $ topo init --dir ./demo $ topo serve --config ./demo/topology.json \ --auth ./demo/auth.json --data ./demo/collector-data \ --observer demo

  3. TUI を開く

    別のターミナルで。あとで topo login がリモートのプロファイルを保存すれば、topo だけで済みます。

    $topo --credentials ./demo/credentials.json
