Topophany — 场所的显现

从哪里出发，经由哪条路径，抵达了什么——依据又是什么。

自托管的网络拓扑与服务可用性监控，在终端中查看。一个没有任何依赖的 Go 二进制文件，既是客户端，也是采集器和观测点。它告诉你测量了什么、从哪里测、测得有多新，从不把没有通过的检查显示为绿色。

安装 在 GitHub 上查看源码
$ go install github.com/WhitenWhiten/topophany/cmd/topo@latest

拖动以旋转地球

有没有出问题？在哪里？

Overview 在你读到任何文字之前就给出答案：一个结论、一张涵盖所有地点和路径的地图，以及需要关注的简短清单。下面是由 TUI 自己的渲染器逐帧录制的 topo preview。证据是合成的，但经过了真实的状态引擎。

02 语义

证据，而非颜色

健康状态、证据来源和新鲜度是彼此独立的字段。没有通过的检查，就不会变绿；没人监控的服务保持 unknown；缓存的视图会明确标出。

默认没有绿色

服务证据状态
●主站Cloudflare ⇢ S1http 200 · 4 秒前由 Cloudflare NRT 应答 · 缓存 DYNAMIC
○家庭面板仅有备注已登记，未监控未配置检查unknown
✖VLESS+Reality 入口DMIT · 洛杉矶tcp 超时 · 6 秒前来自 长沙 MacBook · 3 个样本中 3 个DOWN

健康的行状态列留空，因此亮起的字只有问题。登记了但没有检查的服务不算在线，它是已登记，未监控。

观测点是明确的

每个观测点都从它实际所在的位置测量。从家里看到的失败是那条路径的故障，而不是服务器宕机；事件会显示哪些观测点仍然可以到达。

边缘作出了应答

访客 Cloudflare NRT S1 源站
● HTTP 521 · 边缘在线 ▲ 受影响

在 Cloudflare、Vercel 或其他 CDN 之后，边缘的任何应答——哪怕是错误页——都只能证明边缘本身。只有边缘没有从缓存返回的成功响应，才算作源站的证据。探针会记录是哪个边缘、从哪里作出的应答。

推测就标为推测

FAILED CHECKS
m-exit-dmit-aaitr

OTHER-OBSERVER RESPONSE EVIDENCE
w-exit-s2-aaitr, w-exit-s2-qqpr

HYPOTHESIS (NOT A FINDING)
source/path-specific interference, filtering or
routing fault is possible; blocking authority and
untested protocols are not established
No inference about all IP ports, untested UDP,
physical power or GFW authority.

事件附带失败的检查，以及其他观测点仍然看到的情况。对于没有人测试过的端口或协议，不做任何推断。

它不会断言的事

TCP 连接被接受
只说明连接建立了。不代表应用协议，不代表代理认证，也不代表整条路径。
请求成功，但出口 IP 不符合策略
结果为 policy。可达性与出口策略分开判定。
观测点停止上报
它的视角先变为 stale，再变为 unknown。远端资产不会被标为 down。
主路径失败，候选路径成功
候选路径可用，冗余度下降。它不会断言生产流量已经切换。
采集器不可达
缓存的视图会保留并标为 CACHED，所有项目变为 unknown。

03 架构

一个二进制，三种角色

不需要 CGO、数据库守护进程或 Node.js，外部 Go 模块为零。topo 既是终端客户端，也是采集器和观测点；关闭客户端并不会停止监控。

  • 个二进制文件客户端、采集器和 worker
  • 个外部 Go 模块只有标准库
  • 种发布构建Linux、macOS、Windows · amd64、arm64
  • 个标签页30×10 起即可使用，支持鼠标

观测点

采集器

客户端

topo worker家里的笔记本
topo worker东京的服务器
topo serve --observer采集器自身的基准
观测结果，网络分区期间缓冲
topo serve日志 A · 先 fsync 再 ACK
topo serve日志 B · 相互独立
只读快照
topoTUI，支持故障切换
topo --json供脚本使用的快照

两个采集器，不演共识的戏

worker 各自向两个采集器投递，并在有上限的发件箱中缓冲。重复记录按观测 ID 去除，配置版本不匹配的记录会被隔离。

从设计上就是只读的

没有远程配置 API，没有远程 shell，也没有自动修复。拓扑保存在经过审阅的本地 JSON 中，用 topo edit 编辑，用 topo validate 检查。

有上限，并且明说

默认保留 24 小时或 20,000 条原始记录，并给 worker 的发件箱 32 MiB。配额用满时，探测会报错停止，而不是丢弃证据。

04 探针

它能测量什么

原生探针和显式代理链，外加针对主机上现有工具的只读适配器。

原生探针

  • HTTP · 状态码、正文、头部、出口 IP
  • TCP
  • TLS · 证书校验
  • SSH banner
  • DNS A/AAAA
  • UDP echo · 随机 nonce
  • ICMP · IPv4

代理链

  • HTTP CONNECT
  • HTTPS CONNECT
  • SOCKS5 · 远程 DNS
  • OpenSSH -W · 校验主机

只读适配器

  • Mihomo
  • Tailscale
  • WireGuard

边缘与平台

  • Cloudflare · Workers, Pages
  • Vercel
  • Supabase

05 安装

一分钟上手

提供 Linux、macOS 和 Windows 的预编译归档，或者一条 go install。演示只探测它自己的回环 API，每次运行都会生成新的凭据。

$go install github.com/WhitenWhiten/topophany/cmd/topo@latest

需要 Go 1.26.9 或更新版本。构建时不下载任何模块。

适用于 amd64 和 arm64 的 Linux、macOS 和 Windows 归档，均附带 SHA256SUMS.txt。

最新发布版
$ git clone https://github.com/WhitenWhiten/topophany $ cd topophany $ go build -trimpath -o topo ./cmd/topo

  1. 四处看看

    在内置拓扑和合成证据上体验完整的 TUI。按 x 弄坏点什么。

    $topo preview

  2. 启动采集器

    写出演示拓扑和新的凭据，然后在 127.0.0.1:7447 上提供服务。

    $ topo init --dir ./demo $ topo serve --config ./demo/topology.json \ --auth ./demo/auth.json --data ./demo/collector-data \ --observer demo

  3. 打开 TUI

    在另一个终端里运行。之后用 topo login 保存远程配置，就只需输入 topo。

    $topo --credentials ./demo/credentials.json
