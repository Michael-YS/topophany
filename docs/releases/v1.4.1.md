# Topophany v1.4.1

Released October 21, 2026.

Topophany 1.4.1 reduces collector and worker overhead during steady monitoring,
snapshot polling, checkpoints and outage recovery. Verify downloads against
`SHA256SUMS.txt`.

## Changes since 1.4.0

- **Cheaper collector reads.** Snapshots, incident watchers and attached panels
  share folded evidence. Heartbeat-only updates reuse it, while each read still
  recalculates freshness and liveness. Scoped views load availability history only
  for included checks. One-shot views use a direct build path.
- **Smaller snapshot transfers.** Collectors generate gzip only when negotiated
  and useful. Native clients bound compressed input and decoded JSON. Viewers
  reuse a validated public topology per collector and omit it from later
  transfers while the revision matches. Cached captures refresh after backward
  clock steps, and each encoding is validated once per capture.
- **Less disruptive persistence.** Incremental accounting avoids repeated store
  scans. Automatic checkpoints adapt to checkpoint size within a bounded journal
  budget, capture state once and write in the background. Ingest continues in the
  live WAL; publication retains its subsequent writes, and recovery handles both
  the old journal and the replacement suffix.
- **Bounded worker queues.** Outboxes retain recipient indexes and load payloads
  from disk only for byte-bounded batches. Durable ACK cleanup is batched, and
  partial recipient ACKs go to a separate bounded journal instead of rewriting
  payloads. Successful backfill continues in paced bursts of up to four requests,
  stopping on errors or throttling.
- **Quieter idle workers.** Idle heartbeats default to 15 seconds and stay within
  one third of the observer's freshness window. Queued delivery still polls every
  two seconds; measurements keep their original timestamps and expiry.
- **Build security.** Source builds require Go 1.26.10. The release workflow runs
  `govulncheck` before building and publishing the six platform archives.

The complete [1.4.1 changelog](https://github.com/WhitenWhiten/topophany/blob/v1.4.1/CHANGELOG.md#141---2026-10-21)
records the changes. See [operations](https://github.com/WhitenWhiten/topophany/blob/v1.4.1/docs/OPERATIONS.md)
and [memory budgets](https://github.com/WhitenWhiten/topophany/blob/v1.4.1/docs/MEMORY.md)
for the resource tradeoffs.

## Compatibility and upgrades

Existing topology configuration and measurement contracts remain compatible;
no collector checkpoint or observation journal migration is required. Snapshot
compression and topology omission are negotiated, so older peers can continue
using full JSON snapshots. The monitor stream protocol remains at 1.

Workers now default to at most 20,000 pending outbox records. If an existing
queue exceeds that count, startup refuses it without deleting data. Set
`--outbox-records` to a larger explicit value (up to 1,000,000) to drain it.
Keep the new `acks.jsonl` with all other outbox files when backing up or moving a
worker; partial delivery state depends on it.

`worker --heartbeat-interval` accepts 1 second through 1 minute; the observer's
freshness window can shorten it. Delivery telemetry may update less frequently
while idle. Automatic checkpoint thresholds range from `--checkpoint-bytes`
(default 16 MiB) to `--max-journal-bytes` (default 128 MiB). Set them equal for a
fixed threshold. A larger journal trades fewer rewrites for disk usage and
restart replay; background captures also need temporary index and rollup memory.
Explicit checkpoints and shutdown wait for publication. Persistence errors stop
further writes.

## Downloads

Choose `topophany_1.4.1_<os>_<arch>`: `.tar.gz` for Linux and macOS, `.zip` for
Windows. macOS is `darwin`; Apple silicon is `arm64`, and Intel or AMD 64-bit
systems are `amd64`. Each archive contains `topo` (`topo.exe` on Windows), the
license, the three READMEs and the changelog. `topo version` should report
`Topophany 1.4.1`. Cross-compilation establishes build compatibility, not native
runtime acceptance on every archive architecture.
