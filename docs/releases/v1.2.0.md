# Topophany v1.2.0

Topophany 1.2.0 adds bounded network-software policies and diagnostics, larger
Mihomo inventories and clearer reported evidence, with installation and viewer
correctness fixes. Verify downloads against `SHA256SUMS.txt`.

## Changes since 1.1.1

- Mihomo supports bounded large subscriptions: 4096 names across the combined
  proxy/provider graph, 4096 members per group/provider and 8 MiB inventory
  responses. Built-in names and groups count toward the graph limit. Capacity
  failures remain explicit monitor errors. Subscription-only selected nodes
  are resolved from the existing read-only provider inventory.
- Mihomo adds optional TUN expectations, ordered/set membership comparison,
  independently published provider references, and bounded provider-loading
  settlement with separate publication/load/sample times.
- WireGuard reads public fields and supports AllowedIPs/keepalive expectations.
  Tailscale supports opt-in bounded DISCO/TSMP diagnostics, deterministic peer
  selection, correct timeout classification and missing-time reporting.
- Collector ingress diagnostics count TLS handshake failures in a bounded
  rolling window; viewer sources are pseudonymous by default.
- A transient `429 snapshot_busy` earns one cancellable one-second retry after
  healthy failover is exhausted, reducing offline/cached flicker.
- Vercel's real request ID format yields receiving and ordered routing regions.
  It no longer reports a Vercel PoP or infers arbitrary function locations.
  Historical labels remain role-unverified. Private requests withhold every
  new location label, and the frozen compatibility oracle is unchanged.
- Installer paths, Windows ACLs, authenticated rollback, exported archives and
  alert persistence receive additional validation and resource bounds.
- History follows its snapshot's collector/contract, partial availability
  includes measured coverage, and executable versions identify their source.

## Compatibility and upgrades

Ordinary policy incidents retain the immediate 1.1.1 default. Optional
`policy_threshold` explicitly requires 1..20 consecutive violating samples;
omitted or zero means immediate. Failure/recovery thresholds remain independent.
Mihomo provider loading retains its separate bounded settle window.

Install the new collectors and all native/browser viewers before enabling
new configuration fields, then upgrade workers. Old strict readers reject
fields such as `policy_threshold`; omission preserves old configuration shape.
No new measurement envelope is introduced. Confirmation-setting changes keep
measurement contracts/history, while changes to actual assertions still create
new contracts. Do not downgrade a topology containing unsupported options.

Legacy unsigned installer rollback backups are refused. Keep installer-created
private backup/signing material together. Manual executable rollback requires
matching software/data schemas; never open one collector directory with two
writers. Reopen existing terminal viewers after upgrading their executable.

## Acceptance scope

Native Windows AMD64, Linux AMD64 and macOS ARM64 Mihomo v1.19.32 capacity runs
are recorded in the [acceptance report](https://github.com/WhitenWhiten/topophany/blob/main/docs/acceptance/MIHOMO_2026-10-17.md).
The isolated inventory tests disable TUN, listeners, DNS and health checks and
use fake nodes. Separate production core and HTTPS probes retain reported and
measured evidence respectively. This does not establish physical TUN routing,
every proxy protocol or compatibility with other core versions. The other
archive architectures are cross-build targets unless separately recorded.

The release archives cover Linux, macOS and Windows on amd64 and arm64.
See the linked acceptance records for each native test's exact executable,
core version, configuration scope and result. Cross-builds are not native
runtime acceptance.
