# Topophany v1.4.2

Released October 22, 2026.

Topophany 1.4.2 adds external observation sources, a read-only Beszel Hub
adapter and direct current-state reads without a collector. It also advances the
wire schemas that carry external evidence. Verify downloads against
`SHA256SUMS.txt`.

## Changes since 1.4.1

- **External sources.** A topology can declare `sources` and bind an `external`
  check to one stable upstream object. The worker collects each source once and
  fans the result out to its bindings, within explicit interval, timeout,
  contact freshness, response, page, object and report budgets. Normalized
  resource and status reports carry their own sample identity, upstream time and
  field availability; a failed source read is a collection attempt, never a
  target outage.
- **Beszel Hub adapter.** The production registry ships `beszel`, which reads
  CPU, memory, primary and extra filesystem samples from a Beszel Hub, plus
  optional reported system status. It uses the latest raw `1m` record, maps the
  released v0.21.0 schema and the four-integer `mem` form, and never invents a
  missing value. The adapter is read-only: it does not log in, refresh tokens,
  create records or infer application reachability.
- **Direct current-state reads.** `topo sources list|inspect|save|remove`
  configures private Beszel profiles, and `topo --source direct --profile NAME`
  reads selected systems inside the `topo` process. The same source works for
  `--json`, `status`, `show` and `monitor configure/run`. Direct mode needs no
  collector, daemon, listening port or resource history. Credentials are
  committed before the configuration that references them, and passwords and
  tokens travel through stdin rather than command arguments.
- **Shared resource selection.** Native host checks and external reports now use
  the same ordered resource model. A declared primary disk is required for disk
  selection and is never guessed; each resource expires independently. Monitor
  `server.card.resources.first` is the selected report, with optional source and
  time-basis metadata added without changing existing numeric fields.
- **Schema 3 for external evidence.** Batches and snapshots are schema 3. A
  collector still accepts schema 2 native batches, and a client still reads
  schema 2 native snapshots. External members require schema 3 and are refused
  explicitly by a schema 2 reader. The monitor stream stays at protocol schema 1
  and advertises `direct.schema=1` for direct reads.
- **Recovery and timing fixes.** External evidence survives collector recovery,
  refresh and background checkpoints; format migration is serialized; external
  state is charged to observer quotas and installed before journal replay.
  Admission now advances its future-time reference with monotonic time across
  API and local writes, so a collector clock step-back does not reject valid
  samples. A direct-mode nonrenewable token remains usable until it expires.

## Compatibility and upgrades

Upgrade the collector, every worker and every viewer before adding `sources` or
`external` checks. Older binaries reject the new topology fields instead of
ignoring them. A 1.4.2 collector accepts schema 2 native batches, but an older
collector rejects the schema 3 batches that carry external evidence; an older
client refuses schema 3 snapshots. Existing topologies without sources keep
their native measurement contracts and contract hashes.

The collector writes its checkpoint as schema 1 while no external data exists.
Before acknowledging the first external record it installs a schema 2
checkpoint, even if no external state has been stored yet. Schema 2 is monotonic:
removing sources does not downgrade it. A 1.4.1 or older binary refuses that
checkpoint rather than appending behind state it cannot read, so rollback
requires restoring a matching pre-upgrade backup. There is no supported in-place
downgrade. Back up the collector data directory and worker outboxes before
upgrading.

Direct mode is independent of collector connections and does not read
`credentials.json`. Its profiles and credentials live under a private root
(`os.UserConfigDir()/topophany/direct` by default, or `--direct-root`); on POSIX,
directories are `0700` and files `0600`. `--source direct` keeps no resource
history and starts no background process. It reports what the Hub currently
holds, not whether the machine, application or network is reachable. `status`
exits 2 for current resources needing attention, 3 when no resource is current,
and 4 when every selected source failed contact.

The Beszel adapter is pinned to the released v0.21.0 response schema plus the
four-integer `mem` form. Beszel may change its API in a minor release, so a
structurally different response is not automatically supported. Supply a
read-only PocketBase token in the environment variable named by
`credential_env`; it is sent as `Authorization: <token>`, without a `Bearer`
prefix. Automatic token refresh is outside the read-only adapter. An empty
result can mean missing permission, so it proves neither a healthy system nor a
valid assignment. Keep an application check for end-to-end availability, and
keep tokens out of topology files and repositories.

## Acceptance scope

The offline suite covers external ingestion, recovery, budgets, monitor output
and the production adapter registry through synthetic loopback Hub endpoints.
No live Beszel Hub, user account, real Agent or stored user credential was used.
The optional official-Hub harness remains opt-in and is not part of the offline
suite; forward compatibility with future Beszel versions is not promised.
Direct authentication has synthetic loopback coverage only; logging in to a
user's Hub, arbitrary Beszel/PocketBase versions, SSO and complete MFA flows are
not promised. Cross-builds establish compilation, not native runtime acceptance
on every archive architecture.

## Downloads

Choose `topophany_1.4.2_<os>_<arch>`: `.tar.gz` for Linux and macOS, `.zip` for
Windows. macOS is `darwin`; Apple silicon is `arm64`, and Intel or AMD 64-bit
systems are `amd64`. Each archive contains `topo` (`topo.exe` on Windows), the
license, the three READMEs and the changelog. `topo version` should report
`Topophany 1.4.2`.
