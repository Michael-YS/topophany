# Topophany v1.3.0

Released October 19, 2026.

Topophany 1.3.0 streams its views to desktop widgets and menu bars, gives
collectors and workers memory budgets, and uses much less memory doing the
same work. Verify downloads against `SHA256SUMS.txt`.

## Changes since 1.2.0

- **Monitor streams.** `topo monitor stream` reads NDJSON requests on stdin and
  writes one frame per line on stdout, with no configuration files or locks. A
  new request replaces the running one. `--capabilities` describes what the
  binary supports, `--profiles` lists saved client profiles without tokens or
  URLs, and the `preview` source streams the synthetic scenarios with no
  credentials at all.
- **The terminal's views, as metrics.** `summary.verdict`, `observers.verdicts`,
  `attention.list`, `applications.list`, `servers.list` and `server.card` give a
  panel the same verdicts, attention list and server cards the TUI shows, with
  each piece of evidence keeping its own deadline. Try
  `topo monitor stream < examples/monitor-stream-preview.json`.
- **Memory budgets.** `serve` and `worker` now default to a Go soft target of
  128 MiB and 64 MiB (`--memory-limit`; an existing `GOMEMLIMIT` still wins).
  On Linux, `--memory-max` adds a cgroup v2 hard cap, and the supplied systemd
  units set one. See [Memory budgets](https://github.com/WhitenWhiten/topophany/blob/v1.3.0/docs/MEMORY.md).
- **Less memory.** Checkpoints stream instead of being buffered whole,
  fingerprints and repeated strings are stored compactly, and views share their
  indexes across rows, so large fleets no longer rebuild the topology for every
  card. Retention and the checkpoint format are unchanged.
- **Native macOS host counters.** CPU, memory and process counts come from
  libSystem in process, with no system commands.
- **Reviewed installs.** `topo install --dry-run` prints a `bundle_sha256`
  receipt, and installing requires it back.
- **Fixes** to server-card and panel evidence deadlines, stream replacement,
  reload ordering for incidents and webhooks, expired alerts, location
  inheritance and Windows data-directory permissions.

The complete [1.3.0 changelog](https://github.com/WhitenWhiten/topophany/blob/v1.3.0/CHANGELOG.md#130---2026-10-19)
lists every change.

## Compatibility and upgrades

`topo install --bundle DIR` no longer installs on its own. Review the bundle,
run `topo install --bundle DIR --dry-run`, keep the `bundle_sha256` it prints
outside the bundle, and install with `--bundle-sha256 RECEIPT`. Scripts that
installed bundles unattended need that extra step.

Collectors and workers now start with a Go soft memory target. It is not a hard
limit: the runtime goes over it when the live data needs more, collecting
garbage harder as it does. Pass `--memory-limit 0` to keep the previous
behavior, or raise it for a large topology. Existing systemd units are not
changed; copy the `MemoryMax` settings from `deploy/` if you want the hard cap.
`--memory-max` fails startup on macOS, on Windows and where no cgroup v2 cap can
be set, rather than running without one.

The stream protocol stays at 1. Consumers of older binaries should treat a
missing `profiles` capability as false and check the metric catalog before
requesting `servers.list`. The checkpoint, journal and topology formats are
unchanged.

## Acceptance scope

Memory measurements of the production workers and collector, before and after
the changes, are recorded in the [memory report](https://github.com/WhitenWhiten/topophany/blob/v1.3.0/docs/acceptance/MEMORY_2026-10-19.md).
CI runs the kernel OOM test for `--memory-max` on Linux. The other archive architectures are cross-build targets unless separately recorded.

## Downloads

Choose `topophany_1.3.0_<os>_<arch>`: `.tar.gz` for Linux and macOS, `.zip` for
Windows. macOS is `darwin`; Apple silicon is `arm64`, and Intel or AMD 64-bit
systems are `amd64`. Each archive holds `topo` (`topo.exe` on Windows), the
license, the READMEs and the changelog. `topo version` should report
`Topophany 1.3.0`.
