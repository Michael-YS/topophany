# Topophany v1.1.0

Topophany 1.1.0 adds persistent monitor panels, a browser preview and collector
viewer, and layouts for phones and tablets. It also fixes all five findings
from the October 16 repository security scan.

## Highlights

- **Persistent panels:** configure, preview, export and run monitor panels with
  `topo monitor`, or attach them to a collector or worker. Typed metrics,
  exclusive writers, expiry and lifecycle states keep stale or stopped output
  from appearing healthy. Desktop, worker and compact RunCat templates are included.
- **Browser access:** try the real WebAssembly preview at
  [topophany.com/demo](https://topophany.com/demo/) or connect to your collector
  at [topophany.com/app](https://topophany.com/app/). Enable the viewer with
  `--web-origin https://topophany.com` on your collector. Authentication is
  required; the browser keeps credentials in its current worker session.
- **Device layouts:** `--device` simulates iPhone, iPhone Duo and iPad layouts
  in the terminal; `--device fit` adapts the terminal itself for touch. Browser
  viewers use the phone layout on small screens. These are terminal and browser
  layouts, not a native iOS application. Builds may omit them with `-tags nodevice`.
- **Operational visibility:** bounded rotating service logs, repeated-error
  summaries, specific delivery diagnostics and process-local storage I/O metrics.

## Security fixes

- Refuse existing POSIX managed logs and backups with group or other permissions.
- Replace raw command-line bearer tokens with bounded stdin or private-file input.
- Limit webhook response headers to 32 KiB over HTTP/1 and HTTP/2.
- Package release documentation from allowlisted regular Git blobs at the built
  commit, without following worktree symlinks into runner files.
- Refuse stale snapshot authorities across configuration reloads before reading
  current storage allocation or incident metadata.

## Upgrading from 1.0.0

1. Replace `--credential TOKEN` with saved credentials from `topo login`,
   `--credential-file token.txt`, or `--token-stdin`. The old argument is removed.
   Protect the token file with mode `0600` on POSIX or a restricted ACL on Windows.
   The two temporary input options are mutually exclusive; multi-server profiles
   require an explicit `--server` for an override.

   ```sh
   topo --json --token-stdin < token.txt
   topo --credential-file token.txt
   ```

2. Check the active file and numbered backups selected by `--log-file` before
   restarting a service. On POSIX they must have mode `0600` or stricter; startup
   refuses permissive files until their permissions are corrected.
3. A snapshot request crossing a configuration reload may return
   `503 topology_reloaded` with `Retry-After: 1`. Send a new request to authenticate
   against the current tokens. Requests using a revoked token are refused.
