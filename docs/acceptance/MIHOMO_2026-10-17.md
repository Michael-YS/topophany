## WSL viewer contention acceptance

Production reads reproduced `429 snapshot_busy` while another reader built the
collector snapshot. The saved LAN and overlay addresses lead to the same
collector, so immediate address failover can meet the same lock. The old viewer
marked any failed refresh offline/cached and cleared it on the next success.
Thirty-five old-version reads included three failures through both addresses.

The client now tries healthy failover first. If every endpoint fails and at
least one explicitly returned `429 snapshot_busy`, it waits one cancellable
second and makes one final pass. Authentication, identity, malformed-response,
and other rate-limit errors keep their existing behavior. Persistent busy
responses still return an error; evidence expires under the existing rule.
No server budgets were weakened and no UI error was suppressed.

Forty production WSL reads with the new binary all succeeded; five took over
one second (maximum 1.341 s). Tests cover recovery without an offline flash,
bounded retries, cancellation, immediate healthy failover, authorization
rejection, and continued cached evidence on a true disconnect. Full ordinary
tests, client/TUI race checks and vet passed; focused contention and remote
viewer tests also passed three repeats on macOS and WSL. Native macOS/Linux/Windows binaries
and the browser viewer were rebuilt. This is a bounded acceptance sample,
not a claim that future network failures cannot occur.

Receipt: [WSL contention and recovery](evidence/snapshot-busy-wsl-9917564.json).
